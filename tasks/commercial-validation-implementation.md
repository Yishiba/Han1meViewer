# 商业化验证实现（2026-11-19）

本阶段依据已确认方案，只实现可验证的 14 天观察期与 ¥29／¥49 年费报价研究，不进行真实收款，也不在到期后锁功能。README 当前“不提供商业化服务”的承诺继续有效。

## 当前产品行为

- 设置首页“体验与价格研究”可查看状态、自己的固定研究报价及四档意向选择。回答只保存在本机，不自动上传、不备份、不作为购买订单。
- 首次创建本机研究记录时，已确认过使用须知的升级用户进入 `existing` 组，不计时。新安装用户进入 `new` 组；首次成功加载首页时记录起点。首页请求失败不消耗观察期。
- 观察期 14 天。结束后仍能使用全部现有功能和导出自己的数据。研究报价不会创建订阅或自动扣费。
- 研究记录独立于普通设置，排除 Android 自动备份、设备迁移和项目备份。清数据或卸载会移除它，因此不能用于真实授权或防重试用。系统时间也不可信。
- 两档价格随机分配且在本机固定，研究时必须按方案记录报价组、观察窗口和复核结果。App 内意向按钮仅是本机记录，不能自动计入团队研究样本。
- 2026-11-20 用户认为 ¥49/年过高，正式爱发电方案草稿改为 ¥19.9/年首选、¥9.9/年备选。App 里此前的 ¥29／¥49 是已展示的历史研究报价，本次不改动原始分组或回答，避免把旧回答误算成新价格意向；若要开展新一轮价格研究，需另设研究版本与报价记录。
- 同日爱发电创作者申请向导实际保存年付 ¥19.9 方案时，平台返回“年费不可以低于30元哦～”，方案未创建，`plan_id` 为空；账号手机绑定已完成，创作者申请尚未提交。后续价格选择需用户确认，不能擅自改成 ¥30。数字商品是不同订单类型，现有普通会员订单及 `current_plan` 校验链路不能直接复用。
- 用户随后选择 ¥30/年并授权保存提交。爱发电后台返回新增成功，创作者主页已创建（状态“未认证”），方案设置页重新加载后核对月基础价 ¥5、仅年付、年付优惠价 ¥30、隐藏状态；默认自选金额赞助也已隐藏。平台明确提示“隐藏后仍可以支付购买”，因此不可传播方案直链，不能把隐藏视为停收款。App 付费解锁仍未上线。

## 正式收费前的决策门槛

1. 书面确认经营主体、地区及具体第三方成人内容客户端是否可被收款渠道受理；如 CCBill、Segpay，不能仅凭其网站提及成人业务推定可受理本项目。
2. 核对手续费、固定费用、拒付、退款、税务及最低交易额，重新计算可行的年价；检查目标站点规则、内容权利及公开宣传和 README 承诺。
3. 明确现有用户过渡期限，并单独公告；确认试用到期后保持本地文件访问和个人数据导出，播放中的会话不被中途打断。
4. 接入服务端支付回调与签名授权，客户端只验证授权。正式试用期由可信服务端计时，不能沿用当前本机研究计时。处理支付失败、退款、换机、离线宽限与取消续订。
5. 使用长期保管的正式签名发布商业 APK。2026-11-20 已用自有正式密钥构建 `26112002`，并在 Android 13 真机通过签名轮换覆盖安装、保留原有数据；Android 8–12 仍使用旧证书兼容现有安装，若要在这些系统彻底换签名，需另做数据迁移。

## 2026-11-19 后续权益决策

用户确定：新用户 14 天完整 Pro 体验，到期后浏览、播放、搜索及基础翻译继续免费；本地文件访问、个人数据导出/恢复和手动备份始终可用。智能合集、自动整理、版本备份、加密备份、WebDAV/后台同步等重度功能为未来 Pro 候选。现有用户过渡期保留访问。`ProAccessPolicy` 已把产品权益作为独立规则实现，但**没有接到运行时拦截**；现有 `TrialResearchStore` 仍只是本机研究计时，不可信任为正式授权。等待合法收款渠道、服务端试用期和签名授权可用后再启用。

参考 jasmine 的免费基础版和按时长会员结构，不照搬闭源代码、第三方网站账号绑定、隐藏支付地址或在客户端存放私钥。爱发电有订单查询 API 和 Webhook，但当前产品使用资格及大陆主体合规尚未获平台明确确认，不接入真实付款。

爱发电目前仅回复开发者后台链接，未明确接受当前客户端或回答退款处理。用户提出 jasmine 等项目已有使用先例，因此按爱发电目标渠道继续准备接口；上线仍以本产品自己的账户和平台答复为准。`commerce_server/afdian.py` 已准备服务端查单与 OAuth2 辅助接口：Webhook 仅作查询线索，按官方签名查询订单后验证用户、方案、状态和实付金额；授权码兑换只在服务端进行。jasmine 使用 Rust 不影响这一边界，支付密钥仍只留在服务端。

继续推进后，`commerce_server/server.py` + `afdian_store.py` 已提供可本地联调的 OAuth2 回调、一次性登录票据、会话、无签名 Webhook 二次查单、外部订单入账、当前方案查询与短期授权签发；Android 新增独立 `MembershipApiClient` 校验签名授权、Keystore 加密会话和「设置 → 发电会员」入口（仅配置公开服务 URL/公钥的构建显示）。换机可用同一爱发电身份恢复。打开界面自动刷新状态；401 会清本地会话，断网时本机退出仍可清除会话。24 项服务端测试、Android 全套 Debug 单元测试及隔离模拟器的 Keystore 设备测试通过。仍无商户凭据、HTTPS 回调域名、正式公钥和正式付费拦截；服务端没有生产限流/网关防护，不能公网部署。

## 下载优化作为 Pro 候选（2026-11-19）

- 当前下载管理器默认同时处理 2 个下载任务，设置可调节任务并发；下载 Worker 对单个文件顺序写入，支持 Range 续传和失败重试。**任务并发不等于单视频分片加速**，不能宣称单个视频必然更快。现有速度上限默认无限制，不建议为收费人为降低免费版传输速度。
- Free 候选：普通下载、后台继续、暂停/恢复、断点续传、单任务失败重试、本地播放和文件管理，建议保持最多 2 个并发任务。Pro 候选：更高任务并发（先测 4 个，须尊重站点负载与设备资源）以及未来的批量/自动队列。批量自动队列尚未实现，不能写成当前付费权益。
- `ProductRight` 已加入高级任务并发和自动下载队列的权益标识，仅定义未来边界；**没有在运行时限制并发或下载能力**。正式启用前需验证设置、入队、恢复及 Worker 层的一致执行，处理已有用户当前大于 2 的设置与到期中的在途任务。

### 下载可靠性与性能改动

- 单视频写入缓冲区从 8 KiB 提至 64 KiB；私有文件改用普通随机写入，并在进度入库及完成前显式同步文件。减少每块写入的磁盘同步次数；实际提速仍取决于网络、服务端和存储介质，尚无真机吞吐对照数据。
- 多任务队列只在 Channel 消费者中修改；任务完成带代次，暂停／恢复后旧任务回调不能误删新任务。调整并发设置后立即调度等待队列；排队的重新下载保留其标志。
- 续传严格核对 HTTP 206 的 Content-Range 起点和总长度；若服务端返回错位范围或完整响应覆盖续传，停止写入，避免文件拼接损坏。对 408、429 和 5xx 使用原有 WorkManager 退避重试；网络中断保持已落盘进度。普通下载和恢复仍不加付费限制。
- 评估了 Fetch 的并发／分片能力。它会引入另一套下载数据库和任务生命周期，与当前 WorkManager、Room、SAF 和备份互斥需要整体迁移，因此沿用现有 OkHttp 与 WorkManager。
- 对私有目录、未设置限速且剩余文件至少 16 MiB 的下载，启用两个有界 HTTP Range 请求写入同一预分配文件；最多同时运行 4 条分段连接。每次进度入库前先落盘，数据库只记录连续完成的字节前缀；未完成的后半段会在恢复时重新下载。服务端不支持有界 Range 时回退为单连接，SAF 目录和设置了限速的下载仍走单连接。该优化未做真机吞吐对照，不承诺所有网络更快。
- 下载限速滑块现在即时更新正在使用的 OkHttp 拦截器；已开始的响应沿用其启动时的限速值，后续请求使用新值。
- 验证：98 项 JVM 单元测试通过，含本地 HTTP 服务器的双段写入、Range 不支持回退和断流续传；1 项 Android 真机模拟服务器测试通过，逐字节核对分段写入结果。Debug、Release 构建通过，`git diff --check` 通过。Release 测试包 `0.26.0-release+26111903` 使用与手机现有包相同的 Debug 证书覆盖安装，应用可启动且未见启动崩溃；手机原有应用数据通过 `adb install -r` 保留。尚未用真实站点文件做吞吐量对照。正式商业发布仍需独立签名。
